# 30. 큐레이션(데이터 선별) 방법 정의

논문 방법 절(문제 정식화·비교 선별법)과 비교표에 쓰는 정의다. 구현은 `src/vcp/vla/curation.py`(`METHODS`, `clip_starts`, `select`, `selection_stats`, v3 `select_shared`), 인터페이스는 [28a 계약](28a_VLA_모듈_인터페이스_계약.md), 전체 설계는 [28 재설계 계획](28_VLA_논문_재설계_계획.md)을 따른다.

## 1. 공통 정식화
- 풀: 프레임 t = 1..N, 그룹(에피소드·블록) id g_t. 클립 c = 같은 그룹 안의 연속 L 프레임 {s_c, …, s_c+L−1}.
- 클립 집합 𝒞: 각 그룹(연속 구간)의 시작점에서 L 간격으로 자른 비중첩 클립이다. 끝에 L보다 짧게 남는 꼬리는 버린다(`clip_starts`). 클립은 그룹 경계를 넘지 않는다.
- 예산: 비율 β에 대해 클립 수 k = max(1, round(β·N/L))이다. 유효 클립 수 |𝒞|보다 크면 |𝒞|로 줄인다.
- 통제 변수: 모든 방법은 정확히 k개 클립, 즉 k·L 프레임을 고른다. 방법 간 차이는 "어떤 클립을 고르는가"뿐이다.
- 점수형 방법은 클립 점수 S(c) 상위 k개를 고른다. 동률은 `rng`로 만든 무작위 키로 깨서, 그룹 순서(에피소드 번호)에 따른 편향을 없앤다. NaN 점수는 최하위로 보낸다.
- 표기
  - e_t: 맥락 점수기의 이벤트 점수 P(경고)+P(강한 제동)
  - H_t: 맥락 점수기 출력 분포의 엔트로피
  - a_t: 자차 가속도 명령(행동)
  - r_t: 역 TTC 특징. v2 특징 `lead_inv_ttc`이며 `X_v2[:, ITTC_FEATURE_INDEX]`(= 10)로 얻는다
    (통합 스위트 `vla_curation_suite.py`, `comma_curation.py`는 보행자·이륜차 접근까지 반영하려고 max(`lead_inv_ttc`, `vru_approach`)를 r_t로 넘긴다. `select`는 넘겨받은 배열을 그대로 쓴다)
  - x_t ∈ ℝ^D: 프레임 특징(v2 또는 v1v2)
  - ℓ_t: 전체 데이터로 학습한 정책의 프레임 손실
  - o_t ∈ {0,1}: GT 위험 라벨

## 2. 방법별 정의

| 방법 | 클립 점수 / 선택 규칙 | 필요한 정보 | 온라인/오프라인 | 계산량 | 수집 시점(엣지) 계산 |
|---|---|---|---|---|---|
| random | 𝒞에서 균일 무작위 k개 | 없음 | 온라인(저장소 샘플링으로 스트리밍 가능) | O(\|𝒞\|) | 가능 |
| uniform | 그룹 길이에 비례해 k를 배분(최대 나머지 방식, 그룹 클립 수 상한). 그룹 안에서 m개를 등간격 위치 ⌊(i+½)·n_g/m⌋로 고른다 | 그룹 길이 | 온라인(고정 주기 저장과 같다) | O(\|𝒞\| + G) | 가능 |
| action_trigger | S(c) = max_{t∈c} (−a_t) (감속 크기). 행동이 다차원이면 모든 성분의 최댓값 | 자차 가속도(CAN) | 온라인 | O(N) | 가능 |
| rule_ittc | S(c) = max_{t∈c} r_t | 검출기 + v2 특징 | 온라인 | O(N) | 가능 |
| uncertainty | S(c) = mean_{t∈c} H_t | 맥락 점수기 | 온라인 | O(N) | 가능 |
| event | S(c) = max_{t∈c} e_t | 맥락 점수기 | 온라인 | O(N) | 가능 |
| coreset | 임베딩 z_c = [mean_{t∈c} x_t, std_{t∈c} x_t]를 차원별로 표준화한 뒤, k-center greedy(Sener & Savarese, 2018): 첫 중심은 무작위, 이후 c* = argmax_c min_{j∈선택} ‖z_c − z_j‖² | 프레임 특징 전체 | 오프라인(풀 전체 임베딩 필요) | O(k·\|𝒞\|·D) 시간, O(\|𝒞\|·D) 메모리 | 불가(전체 풀 보관 필요) |
| offline_loss | S(c) = mean_{t∈c} ℓ_t | 전체 데이터 저장 + 정책 학습·추론 | 오프라인·정책 의존 | 정책 학습 비용 + O(N) | 불가(비교 상한 성격) |
| oracle | S(c) = mean_{t∈c} o_t (위험 프레임 비율). 동률은 무작위 | GT 위험 라벨(특권 정보) | 특권 | O(N) | 불가(참고 상한) |
| ours | S(c) = max_{t∈c} e_t + λ·mean_{t∈c} H_t. 상위 k_s = round((1−ρ)·k)개를 점수로 고르고(선택 시 그룹당 최대 cap개), 나머지 k−\|선택\|개는 선택되지 않은 클립에서 무작위로 고른다 | 맥락 점수기 | 온라인 | O(N) | 가능 |

- G: 그룹 수, D: 임베딩 차원(coreset은 특징 차원의 2배).
- 기본 하이퍼파라미터는 λ = 0.5, ρ = 0.3, cap = 없음이다. 실험에서는 검증 풀(시드 150000+)에서만 고른다.
- ours에서 cap 때문에 점수 몫 k_s를 다 채우지 못하면, 남는 몫은 무작위 저장소로 넘긴다. 따라서 총 클립 수는 항상 k다.
- 필요한 입력이 None이거나 길이가 N이 아니면 `ValueError`를 낸다.

### 엣지 계산 가능성에 대한 주의
- 구현은 비교 실험을 위해 풀 전체에서 상위 k개를 고른다(전역 순위). 실제 수집 장치에서는 점수 임계값(예산 β에 맞춘 분위수)이나 스트리밍 top-k 버퍼로 같은 규칙을 근사한다. 표의 "가능"은 클립 점수 자체를 프레임 단위 인과적 연산(현재 클립만 보고)으로 계산할 수 있다는 뜻이다.
- ours의 저장소 몫은 표준 저장소 샘플링(reservoir sampling)으로 스트리밍 구현할 수 있다.
- coreset은 스트리밍 근사(예: 온라인 k-center)가 있지만 본 구현에는 없다. 비교표에서는 오프라인 방법으로 분류한다.

## 5. 기존 API와의 관계
- `select_clips`, `event_coverage`는 기존 VLA 스위트(`experiments/vla_suite.py`)가 쓰므로 유지한다. `select_clips`는 전역 격자(0, L, 2L, …) 시작점을 써서 그룹 경계에 걸친 클립을 버린다. `select`는 그룹별 격자를 쓴다. 따라서 두 함수의 유효 클립 집합은 다를 수 있다.
- `event_coverage`는 그룹 기준 안정 정렬 후 벡터 연산으로 다시 구현했다. 이전 구현(그룹별 반복)과 결과가 같은 것을 무작위 입력 300건으로 확인했다.

## 6. v3 공유 저장소 선별(`select_shared`, docs/33 M1)
### 6.1 동기
v2의 혼합 방법(ours, 트리거 혼합, 오라클 혼합)은 각자 따로 무작위 저장소 몫을 뽑았다. 그래서 두 방법을 비교하면
"점수 몫의 차이"와 "저장소 표집 차이"가 섞인다. 예산 2%에서 저장소 비율 ρ가 크면 저장소 표집 분산이 점수 몫의 차이를
가릴 수 있다(K4 측정 설계 문제, [33](33_v3_핵심지표_벤치마크_개선계획.md) 2절). v3에서는 시드마다 같은 저장소를
모든 혼합 방법이 공유하고, **방법 간 차이를 점수 몫으로만** 한정한다.

### 6.2 정의
`select_shared(method_score, budget_ratio, group, clip_len, rng, reservoir, entropy=None, lam=0.0) -> bool [N]`

1. K = max(1, round(β·N/L))(유효 클립 수 |𝒞|로 상한, `select`와 같음), R = round(ρ·K).
2. rng로 𝒞 전체의 순열 π를 만든다(rng의 첫 소비). 저장소 = π의 앞 R개. 같은 시드라면 method_score와 무관하게 같다.
3. 점수 몫 K−R개 = 저장소 밖 클립(π[R:]) 중 S(c) = max_{t∈c} m_t + λ·mean_{t∈c} H_t 상위.
   동률은 순열 **이후**의 rng 난수로 깨므로 저장소에 영향을 주지 않는다. NaN 점수는 최하위다.
4. `method_score=None`(무작위 기준선): 점수 몫을 π[R:K]로 채운다. 결과는 π의 앞 K개, 즉 공유 저장소를 포함하는
   균일 무작위 K개다. 같은 rng 상태의 `select("random", ...)`와 같은 클립 집합이며 ρ와 무관하다.
5. 선택 프레임 수는 모든 방법에서 K·L이다. 클립 집합 𝒞와 그룹 경계 규칙은 `clip_starts`를 그대로 쓴다.

| 방법(v3 이름) | method_score m_t | λ |
|---|---|---|
| random_shared(무작위 기준선) | None | — |
| CARE(ours) | 이벤트 점수 e_t | 검증에서 선택(λ ∈ {0, 0.5}) |
| 트리거 혼합 | 감속 크기 −a_t | 0 |
| 오라클 혼합 | GT 위험 라벨 o_t | 0 |

- 입력 검사: method_score는 1차원 [N]이어야 한다. λ ≠ 0이고 method_score가 있으면 entropy [N]이 필수다(없으면 `ValueError`).
  예산·저장소 비율 범위는 `select`와 같다.
- v2 `select("ours")`와의 차이: v2는 점수 몫(round((1−ρ)·k))을 먼저 고르고 나머지를 무작위로 채웠다. v3는 저장소를 먼저 고정한다.
  v3에서는 `per_group_cap`을 지원하지 않았다(v4에서 점수 몫 상한으로 추가, 7절). 기존 `select`와 `METHODS`는 바꾸지 않았다(v2 결과 재현용).
- 분석 보조 함수 `shared_reservoir_mask(budget_ratio, group, clip_len, rng, reservoir)`: 같은 시드의 **새** Generator를 넘기면
  `select_shared`가 고르는 저장소 부분만의 마스크를 돌려준다(점수 몫 = 전체 마스크 − 저장소 마스크).
- 스트리밍 구현: 저장소 몫은 시드 고정 저장소 샘플링으로, 점수 몫은 저장소에 들지 않은 클립에 대한 점수 임계값으로 근사할 수 있다
  (2절 "엣지 계산 가능성" 주의와 같다. 본 구현은 비교 실험용 전역 순위다).

### 6.3 검증(`tests/test_curation_shared.py`, 19개)
- 같은 시드에서 점수 4종(무작위, 부호 반전, 전부 0, 주기 패턴)과 None 모두의 선택에 같은 저장소가 포함되고, 다른 시드에서는 저장소가 달라진다.
- 점수 몫이 저장소 밖 클립 중 클립 점수 상위다. λ>0이면 엔트로피만 높은 클립이 뽑힌다.
- 예산(0.02, 0.1, 0.3) × ρ(0, 0.5, 0.95, 1) × 점수 4종에서 선택 프레임 수가 K·L로 같고, 클립이 그룹 연속 구간을 넘지 않는다
  (같은 id가 떨어져 다시 나오는 구간 포함).
- None 기준선: `select("random")`과 같은 클립 집합(ρ 무관), 600개 시드에서 클립별 선택 빈도가 K/|𝒞| ± 5σ 안이고 위치 편향이 없다.

## 7. v4 점수 몫 에피소드 상한(S1)
계획: [36](36_v4_알고리즘_모델_개선계획.md) 2절 S1. 계약: [28a](28a_VLA_모듈_인터페이스_계약.md) "v4 추가 계약(A15)".

### 7.1 동기(계획 시점 가설)
- 점수 상위 클립이 같은 에피소드의 인접 클립에 몰리면 점수 몫의 다양성이 떨어진다.
- 그래서 점수 몫에서 에피소드당 최대 c개 클립만 고르게 한다(v4 고정값 c=1).
- 모든 점수 기반 혼합 방법(CARE·트리거 혼합·오라클 혼합)에 똑같이 적용한다.

### 7.2 정의
`select_shared(..., per_group_cap: int | None = None, info: dict | None = None)`

1. 저장소(6.2절 1·2단계)와 동률 난수 소비는 v3와 같다. 따라서 **저장소는 c와 관계없이 같다**.
2. 저장소 밖 클립을 클립 점수 S(c) 내림차순(동률은 rng)으로 훑는다.
   같은 group 값의 클립을 c개까지만 점수 몫에 넣고, 상한을 넘는 클립은 건너뛴다.
3. 상한 때문에 K−R개를 못 채우면(group 수가 적을 때), 남은 자리는 건너뛴 클립 가운데 점수 순(상한 무시)으로 채운다.
   - 선택량은 v3와 같은 K·L이다.
   - 채운 수는 `info["n_cap_overflow"]`와 INFO 로그로 남긴다.
4. 상한은 점수 몫에만 적용한다. 저장소 클립은 세지 않는다.
5. `method_score=None`(무작위 기준선)이면 상한을 무시한다. 결과는 v3와 같다.
6. `per_group_cap=None`이면 v3와 비트 단위로 같다. c가 그룹당 클립 수 이상이어도 v3와 같다.

- 그룹 단위
  - v3·v4 VLA 스위트(`vla_v3_suite.select_v3`)는 group으로 풀의 에피소드 id(`pool["ep"]`)를 넘긴다. 그래서 상한 단위는 **에피소드**다.
  - comma 실험(`comma_curation`)은 연속 구간 id를 넘긴다.
  - 같은 group 값이 떨어진 두 구간에 나오면 상한은 두 구간을 합쳐 센다.
- 클립은 기존 `clip_starts(group, clip_len)` 정의(같은 group 연속 구간 안의 비중첩 클립)를 그대로 쓴다.
- `info`(선택): dict를 넘기면 다음 키를 채운다.
  - `k`, `n_reservoir`, `n_score`
  - `per_group_cap`(적용 값, 무작위 기준선이면 None)

### 7.4 검증(`tests/test_vla_v4_obs_curation.py` 중 6건)
- c=1(ρ 0.5·0.9): 점수 몫 클립의 에피소드가 서로 다르고, 선택량이 같고, 저장소가 c와 무관하게 같다. 같은 입력의 v3는 몰림이 있다(대조). c=2면 에피소드당 2개 이하다.
- c=1의 점수 몫 = 각 에피소드의 저장소 밖 최고 클립 가운데 점수 상위(동률 없는 점수로 직접 계산해 대조)
- None = 인자 생략(v3) = 충분히 큰 c(시드 5개)
- 상한 부족(3에피소드, 점수 몫 9): 에피소드별 최고 3개 + 나머지 점수 상위 6개, `n_cap_overflow=6`
- 무작위 기준선은 c를 무시함, 잘못된 c(0, −1, 1.5) 거부
