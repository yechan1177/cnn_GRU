# 33. v3: 핵심 지표(KPI) 중심 벤치마크·방법 개선과 전체 재실험 계획

- 작성: 2026-10-04
- 배경: v2(exp_110)는 주행 예산 2%에서 CARE의 우위를 확증했다. 그러나 아래 지표가 약하거나 측정되지 않았다.
- 사용자 지시: "핵심 지표를 골라 그 지표에 맞게 조정"한다. 범위는 벤치마크 수정과 전체 재실험이다.

## 1. 핵심 지표(KPI)와 목표

| ID | 지표 | 정의 | v2 값 | v3 목표(사전 선언) |
|---|---|---|---|---|
| K1 | 폐루프 성공률(주 예산 2%) | 무충돌 ∧ 진행 ≥ 0.8×전문가 | CARE 0.751(시드 3), 확증 세트 0.736 | ≥ 0.80 |
| K2 | 데이터 효율 | 성공률(CARE 2%) / 성공률(전체 100%) | 0.84 | ≥ 0.90 |
| K3 | 위험 시나리오 성공률(2%) | 급제동·끼어들기·보행자 횡단·정체 | 0.671 | ≥ 0.75 |
| K4 | 점수기 고유 기여 | CARE − (같은 저장소 + 감속 트리거 점수), 2% | +0.066(CI가 0 포함) | CI 하한 > 0 |
| K5 | 도메인 일반화(AMR) | AMR CARE − 무작위, 2% | −0.032(CI가 0 포함) | ≥ 0(비열등 한계 −0.03) |
| K6 | 언어 지시 준수 | 반사실 평가에서 언어 입력이 줄이는 속도 추종 오차 비율 | 측정 불가(누출) | ≥ 30% 감소 |
| K7 | 실영상 제동 시작 예측 | 개루프 AUROC(전체 데이터) | 0.52 | ≥ 0.65 |

목표 달성 여부는 결과 그대로 보고한다. 미달 지표를 숨기거나 테스트 결과를 보고 설정을 바꾸지 않는다. 튜닝은 검증 세트에서만 한다.

## 2. 진단(v2 원자료)

- **AMR 실패**: 전체 데이터 정책도 성공률이 0.47이었다. 실패는 다음 시나리오의 주행 중 충돌에 몰려 있었다.
  - robot_follow_agent: 6/12
  - robot_agent_stop: 9/12
  - robot_crowded: 10/12
  - 공통점은 정밀한 거리 판단이 필요한 정지·추종 상황이다. 64×64 렌더 영상만으로는 근거리 간격을 읽기 어렵다.
- **실영상 AUROC 0.52**: 사전학습 없는 CNN이 64×64 실영상 17분으로 제동 단서를 학습하지 못했다.
- **언어 누출**: 초기 속도 = 목표 속도 × U(0.85, 1)로 정해져 지시 정보가 초기 상태에 담겼다.
- **K4 측정 설계**: 저장소 클립이 방법마다 달라, 저장소 표집 분산이 점수 몫의 차이를 가렸다.

## 3. 개선

| 항목 | 내용 | 대상 KPI |
|---|---|---|
| P1 정책 입력 확장 | VLA-lite에 검출 특징 토큰(v1+v2, 32차원 × 프레임 t, t−2)을 추가한다. 영상·언어·속도와 함께 FiLM 이후 결합한다. 시뮬레이터 폐루프에서는 노이즈 검출로 온라인 계산하고, 실영상에서는 YOLO 검출 특징을 쓴다 | K1, K2, K3, K5, K7 |
| B1 언어 누출 제거 | 스타일이 있을 때도 초기 속도를 시나리오 기본 속도 × U(0.85, 1)로 정한다. 지시 목표 속도와 분리하며, 난수 소비 순서는 유지한다 | K6 |
| B2 반사실 언어 평가 | 같은 시나리오·시드를 세 스타일 지시문으로 각각 평가한다. 언어 있음/없음 정책의 속도 추종 오차와 스타일별 간격 분리도를 비교한다 | K6 |
| B3 AMR 충돌 처리 | 충돌 시 자차를 뒤로 밀지 않는다(플래그 `collision_pushback=False`). 전문가 기준 거리가 음수가 되는 결함을 제거한다. 기존 회귀 fixture는 기본값 True로 유지한다 | K5 |
| M1 공유 저장소 선별 | 무작위 저장소 클립을 시드별로 먼저 뽑아 모든 혼합 방법이 공유한다. 점수 몫만 방법마다 다르게 고른다. 무작위 기준선 = 공유 저장소 + 무작위 몫 | K4 |

## 4. 실험(exp_120_vla_v3)

| 단계 | 내용 | 평가 세트 |
|---|---|---|
| 준비 | 새 풀(B1·B3 반영)을 만들고, 점수기는 v2 점수기를 재사용(초기 라벨 셋 동일)한다 | — |
| 파일럿 | 정책 v3 학습 단계 수를 확인한다(전체·무작위 2%, T∈{3000, 6000}) | 검증 |
| 튜닝 | 공유 저장소 기준 λ∈{0, 0.5}, ρ∈{0.8, 0.9, 0.95}, 2%, 시드 0 | 검증 |
| 본 실험(주행) | 2%: 무작위·CARE·트리거 혼합·오라클 혼합·감속 트리거 단독, 시드 10개. 100%: 시드 5개. 1%·5%: 무작위·CARE, 시드 5개 | 새 테스트(시드 800000번대) |
| 언어(K6) | CARE 2%·전체 100%, 언어 있음/없음, 시드 5개, 반사실 평가 세트 | 반사실(시드 850000번대) |
| AMR(K5) | 2%: 무작위·CARE·트리거 혼합, 시드 5개. 100%: 시드 3개. 튜닝은 AMR 검증에서 | AMR 테스트 |
| 실영상(K7) | 정책 v3(특징 토큰), 10·20%: 무작위·감속 트리거·CARE·오라클, 100%. 5-fold × 시드 2 | 블록 교차검증 |

- 사전 등록: 테스트 실행 전에 `docs/34_v3_사전등록.md`를 커밋한다.
- 통계: 시드·에피소드 계층 부트스트랩을 쓰며, K4·K5는 Holm 보정한다.
