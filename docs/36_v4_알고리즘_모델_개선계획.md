## 2. 개선(모두 기본값에서 v3와 동일하게 동작)
| ID | 종류 | 내용 | 대상 |
|---|---|---|---|
| P2 | 모델 블록 | **시간 특징 인코더**: 특징 이력 H프레임(t, t−s, …, t−(H−1)s; 기본 H=8, s=2, 약 1초)을 GRU(32→64)로 요약한다. v3의 2프레임 MLP를 대체한다 | K1, K3, K5 |
| P3 | 모델 블록·학습 | **위험 맥락 보조 헤드**: 융합 표현에서 맥락 6클래스를 예측하는 선형 헤드를 둔다. 타깃은 CARE 점수기의 확률(수집 시점에 이미 계산하는 값, 특권 정보 아님)이고, 손실은 soft CE × α다. 추론 때는 쓰지 않는다 | K2, K3 |
| T1 | 학습 | **지시문 드롭아웃**: 학습 중 확률 p로 지시문을 빈 지시(PAD)로 바꾼다. 언어 없는 경로를 함께 배워 적은 데이터에서 FiLM 과적합을 줄인다 | K6 |
| S1(기각) | 선별 알고리즘 | **점수 몫 에피소드 상한**: 공유 저장소 선별의 점수 몫에서 에피소드당 최대 c개 클립만 고른다(점수 순, 저장소에 없는 클립). 모든 점수 기반 혼합 방법(CARE·트리거 혼합·오라클 혼합)에 똑같이 적용한다 | K4, K3 |

| P4 | 학습(추가) | **위험 가중 손실**: 표본별 행동 손실에 가중치 1 + β·e_t를 곱한다(배치 안 평균 1로 정규화). e_t는 수집 시점 CARE 점수기의 위험 확률이며 특권 정보가 아니다. β=2로 고정한다 | K3, K5 |

### 2.0c P6 추가 근거(주행 개발 세트 반사실 결과, 2026-10-04 22:00)
- 주행 개발(21:11)에서 "전부"는 CARE 2% 성공률 0.817로 v3 0.722보다 높았다. 그러나 반사실 개발 세트의 속도 오차는 언어 있음 2.53, 언어 없음 2.14 m/s였다. 언어가 여전히 속도 추종을 돕지 못한다(K6 위험).
- v3 반사실 결과를 스타일별로 나눠 보면, CARE 2% 정책은 언어 유무와 관계없이 '보통'·'민첩' 지시에서 목표 속도(약 16 m/s)보다 느리게 달린다(평균 12~14 m/s). 전체 데이터 정책은 언어가 있으면 오차가 절반으로 준다.
- 해석: 지시문의 목표 속도("60 km/h")는 숫자 토큰 하나하나가 별개 어휘다. 2% 데이터에서는 숫자 토큰별 예시가 적어 정책이 숫자 → 목표 속도의 대응을 배우지 못한다.
- **P6 지시문 수치 목표 인코딩**: 어휘의 숫자 토큰을 단위 규칙(주행 정수 = km/h, 로봇 소수 = m/s)으로 정규화 목표 속도 g로 바꾸는 결정적 표를 둔다. 여기서 [g, 있음, g − v_t]를 만들어 작은 MLP(3→16→16)로 헤드에 결합한다.
  - 언어를 쓰지 않는 절제 모델에서는 꺼진다. 빈 지시(드롭아웃)에서는 0이다.
  - 학습 가능한 파라미터는 MLP뿐이다.
- 평가와 채택
  - "전부+P6"을 주행 개발(시드 3)·반사실 개발(시드 2 × 언어 있음/없음)과 AMR 개발(시드 3)에서 잰다.
  - "전부"가 뽑혔을 때만 다음 조건을 모두 만족하면 "전부+P6"으로 바꾼다(결과 전 확정).
    - "전부+P6"의 개발 성공률이 "전부" 이상이다.
    - (주행) 반사실 개발 세트의 언어 있음 속도 오차가 "전부" 이하다.

### 2.0d P7 추가 근거(주행 P6 개발 결과, 2026-10-04 22:35)
- "전부+P6"은 주행 개발 성공률 0.837로 "전부" 0.817보다 높아 채택됐다(AMR도 0.343 > 0.315).
- 그러나 반사실 개발 세트의 속도 오차는 언어 있음 2.52, 언어 없음 2.14 m/s로, P6 전("전부" 2.53/2.14)과 같았다. 목표 속도 숫자를 받아도 정책이 그 속도까지 가속하지 못하는 저속 편향이 남는다.
- **P7 목표 속도 잔차 헤드**: 정책 출력 = 기준 행동 a0 + 학습 잔차다.
  - a0 = clip(k·(g − v_t), ±0.5)이고 정규화 단위다. k는 물리 이득 0.5 s⁻¹에 속도 스케일/가속도 스케일을 곱한 값으로, 주행 3.75, AMR 1.5다.
  - g는 P6이 지시문에서 읽은 목표 속도다. 지시문에 숫자가 없으면(빈 지시, 언어 절제) a0 = 0이다.
  - 해석적 비례 제어기 위에 잔차를 학습하는 구조(잔차 정책)로, 학습 파라미터가 없다.
- 해석 주의: K6를 달성하면 그 효과의 일부는 해석적 제어기 덕분이다. 원고에서 이를 밝히고, "전부+P6"(제어기 없음)의 반사실 결과를 함께 보고한다.
- 채택(결과 전 확정): "전부+P6"이 뽑혔을 때만 다음을 모두 만족하면 "전부+P7"로 바꾼다.
  - "전부+P7"의 개발 성공률이 "전부+P6" 이상이다.
  - (주행) 반사실 언어 있음 속도 오차가 "전부+P6" 이하다.

### 2.1 개발 실험 전 수정(2026-10-04, A15 측정)
- **S1 기각.** v3 CARE 2%의 점수 몫 36클립은 이미 서로 다른 36개 에피소드에서 나왔다(시드 0·1·2 모두). 그래서 c=1이 CARE 선택을 바꾸지 않는다. 바뀌는 것은 트리거 혼합뿐이고(31 → 36 에피소드, 점수 몫 위험 비중 0.64 → 0.58), 이는 비교 기준선만 바꾼다. 1절의 K4 진단은 잘못 읽은 수치에 근거했다. "CARE 0.146 / 트리거 0.131"은 점수 몫이 아니라 전체 선택의 위험 비중이었고, 점수 몫만 보면 CARE 위험 비중은 약 0.80이다. 따라서 S1은 개발 비교에서 뺐다. K4에 대한 별도 개선은 이번 v4에 없으며, P3이 위험 클립 학습을 강화하는 간접 효과만 기대한다.
- **특징 프리롤.** 학습 데이터는 클립 단위이고, 특징 이력(H=8, s=2)이 클립 시작에서 잘리면 폐루프(에피소드 시작에서 자름)와 클립 앞 14프레임이 달라진다. 특징은 프레임당 32 float라 저장 비용이 영상에 비해 무시할 만하다(클립당 14×32×4 B ≈ 1.8 KB). 그래서 큐레이션 내보내기에서 클립 앞 (H−1)·s 프레임의 특징을 함께 저장한다고 두고, 학습 때 특징 이력은 에피소드 시작에서 자른다(`PolicyData.feature_group`). 영상·행동은 그대로 클립 안에서만 쓴다.

## 6. 인터페이스 계약(A14·A15 공통)
- 관측 `"features"`: float32 [B, H, D]. 인덱스 k는 프레임 t − k·s(같은 에피소드 시작에서 잘라 냄)의 특징이다. k=0이 현재 프레임이다.
  - H=2, s=2이면 v3와 똑같은 [B,2,D]다.
  - 학습(`PolicyData.observation`)과 폐루프(`FeatureHistory`)가 같은 규칙을 쓴다.
- `PolicyConfig`
  - 새 필드: `feature_history: int = 2`, `feature_stride: int = 2`, `feature_encoder: str = "mlp"`(`"gru"`), `aux_weight: float = 0.0`, `aux_classes: int = 6`, `lang_dropout: float = 0.0`
  - 기본값이면 v3와 비트 단위로 같다.
- `PolicyData`: `aux_targets: np.ndarray | None = None` [N, aux_classes](점수기 확률)를 받는다. 관측 생성은 `feature_history`·`feature_stride` 인자를 따른다(`observation(idx, history=2, stride=2)`).
- `FeatureHistory(batch, history=2, stride=2)`. `run_closed_loop(..., feature_history=2, feature_stride=2)`.
- `select_shared(..., per_group_cap: int | None = None)`: None이면 v3와 같다.
