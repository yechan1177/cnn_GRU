# 태스크 기록 규칙

## 목적
- 작업 상태를 추적 가능하게 만든다.
- 새 스레드에서도 바로 이어서 진행할 수 있도록 한다.

## 기본 규칙
- 작업 시작 전에 태스크 문서를 생성하거나 기존 문서를 갱신한다.
- 태스크 문서는 체크리스트 형태로 작성한다.
- 완료 여부는 즉시 반영한다.
- 실제로 끝나지 않은 항목은 완료로 표시하지 않는다.

## 권장 형식
```md
# TASK_XXX_작업이름.md

## 목적
- 이 작업으로 무엇을 해결하는지 적는다.

## 체크리스트
- [ ] 범위 확정
- [ ] 구현
- [ ] 문서 반영
- [ ] 검증
- [ ] Git 반영

## 검증 메모
- 실행한 명령
- 결과 요약
```

## TODO 관리 규칙
- 공통 TODO에는 현재 저장소 전체 기준 진행 상태를 반영한다.
- 새로운 작업이 생기면 TODO에도 한 줄로 추가한다.
- 완료한 작업은 관련 태스크 문서와 TODO 양쪽 모두 갱신한다.

## 기록 범위
- 무엇을 바꿨는지
- 왜 바꿨는지
- 어떻게 검증했는지
- 아직 남은 위험이 있는지

## 피해야 할 것
- 코드만 바꾸고 태스크 문서를 남기지 않는 것
- 스모크 테스트도 하지 않고 검증 완료로 표시하는 것
- 작업 범위 밖의 변경을 태스크에 섞어 기록하는 것
