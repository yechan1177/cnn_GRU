# 문서 및 코드 규칙

## 문서 규칙
- README, docs, tasks, 코드 주석과 docstring은 한 언어로 일관되게 작성한다.
- 코드 변경 시 관련 문서도 함께 갱신한다.
- 결과 수치는 출처와 검증 범위를 함께 설명한다.
- 처음 보는 사람도 따라할 수 있도록 실행 경로와 명령을 남긴다.

## 코드 규칙
- 타입 힌트를 사용한다.
- config 기반 설계를 우선한다.
- 하드코딩을 최소화한다.
- 예외 처리와 로깅을 포함한다.
- 테스트 가능한 구조를 유지한다.

## 함수 작성 규칙
- 함수 하나는 하나의 책임을 갖도록 쪼갠다.
- 입력과 출력이 무엇인지 드러나는 이름을 사용한다.
- 바로 이해하기 어려운 계산에는 짧은 주석을 추가한다.
- 반복해서 쓰는 로직은 보조 함수로 분리한다.

## 방어 코드 규칙
- 입력이 없거나 비정상일 때 어떻게 처리할지 명확히 둔다.
- 외부 파일, 모델 가중치, 경로 의존성은 존재 여부를 먼저 확인한다.
- 추론/실험 코드에서도 실패 시 전체 파이프라인이 완전히 깨지지 않도록 최소 방어 로직을 둔다.

## 코드 리뷰 기준
- 이 코드가 왜 이렇게 구성되었는지 설명 가능해야 한다.
- 재현 가능한가
- 예외 상황을 처리하는가
- 문서와 실행 방법이 함께 남아 있는가
- 나중에 다른 사람이 응용할 수 있는가
