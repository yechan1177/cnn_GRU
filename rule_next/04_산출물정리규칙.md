# 산출물 정리 규칙

## 목적
- 실험 결과와 시각화 자료를 다시 찾기 쉽게 정리한다.
- 문서, 발표자료, GitHub 정리까지 한 번에 이어질 수 있도록 한다.

## 기본 원칙
- 실행 결과는 이름만 보고도 목적을 알 수 있게 저장한다.
- 실험 결과와 수작업 문서는 섞지 않는다.
- 그림, 표, 로그, 설정값을 함께 남긴다.

## 권장 저장 범위
- 시스템 구조도
- 데이터 흐름도
- 모델 구조 요약도
- 실행 결과 스크린샷
- 실험 결과 표
- 성능 비교 표
- 에러 및 실패 사례
- 엣지 케이스 자료
- 실행 로그 및 설정값
- 참고 문헌 및 참고 자료

## 권장 폴더 역할
- `experiments/`: 학습, 실험 설정, 로그, 체크포인트, 결과표
- `artifacts/`: 스크린샷, 비교 그래프, 클립, 문서용 이미지
- `docs/`: 설계 문서, 재현 가이드, 해석 문서
- `tasks/`: 작업 이력과 체크리스트

## 저장 규칙
- 파일명에는 가능한 한 목적이나 입력 이름을 포함한다.
- 그래프와 표는 원본 데이터 파일(CSV/JSON/MD)도 함께 남긴다.
- 발표나 논문에 들어간 그림은 루트 또는 `artifacts/`에 다시 찾기 쉽게 정리한다.

## 검증 규칙
- 산출물을 만들었으면 생성 경로를 문서나 태스크에 기록한다.
- 사람이 직접 확인한 해석과 자동 계산 결과는 구분한다.
